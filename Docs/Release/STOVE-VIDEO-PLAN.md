# BALL-A-RETRO 심의 영상 촬영표

대상: 새 제출 후보 **submission-v10**, Windows 64비트 0.1.0 / 소스 `2a537de`. 새 STOVE 빌드 ID는 아직 미정이다.
확정 소스 커밋은 `D:/ball-a-retro-validation/stove-release-20261108/submission-v10/evidence/source.json`에 기록한다.
기존 STOVE 빌드 **53114** / 소스 `59cdfe7`에는 새 워프·로딩 효과, 시작 시 광과민성 안내,
로비 종료 버튼·영문 체크리스트 수정이 포함되어 있지 않으므로 이번 제출 영상의 촬영 대상으로 사용하지 않는다.
**v10 업로드 → DRM 적용 완료 → STOVE 클라이언트 설치·실행 시험 통과** 후 새 빌드 ID를 기록하고 촬영한다.
v10은 기존 드로우콜 최적화를 유지하면서 룰렛 이후 선택 화면 가림, 커서 잔존, 튜토리얼 카메라 이탈을 수정하고,
선택지 네온 이미지 9종을 새로 생성하여 카드·보유 목록·결과 화면에 적용한 후보다.
업로드와 실제 촬영은 사용자가 진행한다. 수정 전 녹화본 두 개는 아래와 같이 받았으며, 새 빌드의 제출 영상 완료로 표시하지 않는다.

## 제출 요건과 촬영 기준

[STOVE 공식 체크리스트](https://studiodocs.onstove.com/release/ratings/자체-심의-체크리스트)를
2026-11-08 브라우저에서 확인했다. 초반·중반·후반은 각각 7분 이상이며, 멀티 엔딩은 모두
첨부한다. 지정된 등급 관련 장면이 있으면 해당 내용도 포함한다.

이번 작업의 촬영 기준은 1920×1080, 30fps 이상, 실제 게임 소리가 포함된 MP4다.
해상도·프레임률은 이 작업의 권장값이며 STOVE가 이 페이지에 명시한 필수 수치가 아니다.
한국어로 촬영하고 대사를 끝까지 읽을 수 있게 진행한다. 원본은 그대로 보관한다.
시간을 맞추려고 같은 영상을 반복하거나 정지 화면·슬로 모션으로 늘리지 않는다.
실제 게임 길이가 짧아 요구 구간을 확보할 수 없으면 전체 플레이를 보존하고 그 사유를 명시한다.

## 녹화 준비

1. v10 업로드·DRM 적용·클라이언트 시험이 끝났는지 확인하고, 새 STOVE 빌드 ID와
   `evidence/source.json`의 소스 커밋을 촬영 기록에 남긴다. STOVE 스튜디오 테스트에서 해당 빌드를 실행한다.
2. 설정에서 한국어, 화면 해상도, 들을 수 있는 게임 음량을 확인한다. 제출 촬영은 게임에 포함된
   시각 효과를 보여주도록 **전체 효과를 켠 상태**를 기본으로 한다. 시작 안내에서는 `계속하기`를 선택하고
   효과 설정을 확인한다. 개인 시험에서는 `효과 줄이고 계속하기`를 선택할 수 있다.
   촬영에 사용한 효과 설정은 기록하고, 효과를 줄인 장면이 있으면 해당 구간을 명시한다.
   촬영 후 원래 언어·음량·효과 설정으로 되돌릴 수 있다.
3. 현재 설치된 Xbox Game Bar를 사용한다. 게임에 포커스를 두고 사용자가 직접
   **Win + Alt + R**을 누르면 녹화 시작/정지다. 마이크는 끄고 게임 소리를 포함한다.
4. 먼저 약 15초간 로비에서 버튼을 누르며 시험 녹화를 하고 정지한다.
   검은 화면, 무음, 녹화 대상 오류가 없는지 확인한 뒤 게임을 다시 실행한다.
   광과민성 안내 화면을 닫기 전에 본 촬영을 시작하여, 안내 내용을 읽을 수 있게 담는다.
5. 저장 위치는 `C:/Users/sehyeon/Videos/Captures`다. 게임 영상만 검토 대상으로 사용한다.
   원본 파일은 이동·삭제하지 않고 복사하여 작업한다.

단축키와 MP4 저장 경로는
[Microsoft Game Bar 안내](https://support.microsoft.com/en-gb/accessibility/windows/use-a-screen-reader-to-record-your-screen-with-xbox-game-bar)를 참고한다.
현재 자동 조작 도구가 게임 화면을 읽지 못하므로 녹화 시작/정지와 플레이는 사용자 조작이 필요하다.

## 엔딩 도달 조건 — 실제 출시 씬과 코드 기준

- 본게임은 3라운드이며 목표 점수는 **2,000 → 4,000 → 6,000**이다.
- 1·2라운드는 목표 달성 시 다음 라운드로 이동한다.
- 3라운드 목표 달성 시 즉시 결과 화면으로 끝나지 않고 **기록 도전**이 시작된다.
  이후 남은 공을 소진하여 판이 끝나면 성공 엔딩으로 이어진다.
- 최종 목표 달성 전 공을 소진하면 실패 엔딩이다. 플리퍼 자원 소진에 따른 실패도
  같은 Ending2 대사를 사용하지만 실패 사유 UI가 다를 수 있으므로 가능한 경우 함께 담는다.
- 성공 Ending1에는 `이런 젠장! 내 돈!!!! 내 뽀찌!!!!!`가 포함된다.
  실패 Ending2에는 참가비를 보관한다는 표현이 포함된다.

근거: `Assets/MainScenes/Main_Scene_Game.unity`의 goalRound·targetScores·엔딩 ID,
`KHS_Script_ScoreManager.EvaluateTarget/HandleBallOut`,
`PSH_Script_GameOverSequenceDirector`, `Assets/Resources/dialogues.csv`.
점수·공 위치·라운드 값을 강제로 바꾸어 일반 플레이인 것처럼 제출하지 않는다.
별도 심사용 치트를 사용하게 되면 사용 구간과 방법을 설명서에 명시한다.

## 후처리와 검증

작업 폴더: `D:/ball-a-retro-validation/stove-release-20261108/submission-v10/review-video`.
`raw`는 원본 복사본, `submission`은 검증 후 제출할 MP4, `evidence`는 검사 결과다.

`Tests/Release/Review-Video.py`는 실제 영상의 구간 추출, 전체 디코딩 검사, 해상도·음성·분량
점검과 시간 표시가 붙은 미리보기 12장을 만든다. 원본·결과 파일 해시도 기록한다.
속도 변경·반복·정지 화면 추가 기능은 없다. 기존 결과를 덮어쓰지 않는다.
기술 검사 통과만으로 초·중·후반 및 엔딩 내용이 검증됐다고 표시하지 않는다.

최종 제출 전에는 5개 파일의 실제 내용, 초·중·후반 각 420초 이상,
두 엔딩의 대사·결과 화면 완결, 게임 음성, 민감 정보 노출 여부를 사람이 검토해야 한다.
이후 새 STOVE 빌드 ID·소스 커밋·촬영 시 효과 설정과 파일별 길이·해상도·SHA256,
콘텐츠 타임코드를 제출 목록에 기록한다.
