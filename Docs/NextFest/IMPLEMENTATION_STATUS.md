## 증거와 재현

검사 루트: `D:/ball-a-retro-validation/nextfest-20261111/`. 각 모델/UI 실행 폴더의 `results.xml`, `unity.log`를 보존한다. 실제 씬 결과는 `full-scene-v3/full-scene-audit.json`, 3언어 선택/Tab 및 두 엔딩 PNG에 있다. 스크린샷은 실제 카메라와 UI를 1920×1080 오프스크린 렌더한 것이며 데스크톱 조작 녹화가 아니다.

- `Tests/RunProgression/Run-Tests.ps1 -OutputRoot <새 외부 폴더> -IncludeNextFest`: 조합·경계·추첨·재추첨 및 CPU 측정.

- `Tests/CameraChoices/Run-Tests.ps1 -OutputRoot <새 외부 폴더>`: 실제 카메라/선택 컴포넌트와 이벤트 픽스처.

첫 씬 검사 v1은 기능 44개를 통과했지만 오프라인 자동 제출 메시지를 실패로 집계했다. v2는 재시작 때 인트로가 다시 나온다는 검사 가정이 틀렸다. 실제 코드의 1회 인트로 규칙에 맞춰 검사를 고쳤다. v3은 정확히 `Steam login required`인 자동 제출 2건을 예상된 오프라인 결과로 별도 기록하며, 다른 오류는 여전히 실패 처리한다.

실제 씬을 통한 재추첨 버튼 진입·Tab 처리 메서드·카드 Button 콜백은 검증했지만, 배치 에디터의 네이티브 마우스 캡처와 물리 키 입력은 수동 검사 대상이다. 공은 고정하고 정상 득점 API를 주입했으므로 자연스러운 한 판의 물리 플레이나 재미를 통과했다고 보고하지 않는다.

최종 코드 기준은 `894be69`. 변경한 production 파일 22개의 저장소/격리 스냅샷 SHA-256가 일치함을 `final-source-hashes.json`으로 확인했다. `full-v2-build/player`는 중간 빌드이므로 최종 전달용으로 쓰지 않는다.

## 알려진 문제 / 아직 주장하지 않는 것

- 보너스 맵 누적 총점 곱셈의 과도한 우위는 여전히 밸런스 과제다. 중복 트리거 정산과 정수 범위 초과 방어는 구현·검사했지만, 정상 재진입을 반복하는 공략의 기대 점수까지 균형이 맞았다는 뜻은 아니다.
- 현재 본편은 남은 공 수에 비례해 강화 횟수가 늘어나는 구조다. 이번에 임의로 새 라운드/영구 성장 규칙을 확정하지 않는다.
- 물리 플레이의 재미·숙련도별 밸런스·저사양 FPS는 자동 테스트 통과만으로 입증되지 않는다.
- Steam 인증·실제 서버 업로드와 공개 출시 승인은 별도 항목이다. 본편 로컬 검증을 현행 데모 출시 확인으로 보고하지 않는다.
- CPU 미세 측정은 11배치 × 추첨 2,000회/득점 10,000회. 이 Mono 환경의 `GC.GetAllocatedBytesForCurrentThread`가 할당이 있는 추첨에서도 0을 반환하므로 JSON의 0을 무할당 증거로 사용하지 않는다. FPS/프레임 할당은 별도 측정 대상이다.
- 첫 조합 추가 직후 미세 측정: Roll3 13.26725 μs, 직접 득점 0.10944 μs. 새로운 후보 2장과 조건 검사 비용이 포함되며 최종 추첨 구현 후 다시 비교한다.
- 등급 추첨·점수 상한 반영 후 bonus-bounds-green: Roll3 중앙값 12.04435 μs / 배치 p95 15.50315 μs, 직접 득점 0.10692 μs / 배치 p95 0.149 μs. 변경 전 대비 각각 약 2.80배/3.59배, 절대 증가 약 7.74 μs/0.077 μs. 프레임 루프가 아닌 이벤트 호출 비용이며 FPS 개선/동등을 주장하지 않는다.
- 고정 데모 회귀 frozen-demo-v1 및 frozen-demo-final: 각각 24/24 통과. 데모의 기존 균등 추첨, 3선택, 기존 충전 유지 규칙을 검사한다. 이후 일본어 버튼 폭 수정도 본편 조건 안에만 있다.
- 중복 보너스 정산은 bonus-red에서 30,000점 예상에 150,000점으로 재현. 같은 보고서의 점수 상한 검사 2개는 라운드 전환을 피하지 못한 테스트 준비 문제였으며, 기록 도전 상태에서 측정하도록 바로잡아 green을 통과했다. 이를 음수 재현 증거로 인용하지 않는다. 기존 음수 오버플로의 별도 주입 재현은 QA 담당 결과와 구분한다.
- 참고 렌더 측정 full-scene-v3: 에디터 배치 Game View 실제 크기 640×480, 정지 공, 60프레임 준비 후 240프레임의 중앙값 5.898 ms / p95 6.493 ms. 단일 변경 후 표본이며 비교 기준이나 1080p 플레이어 FPS로 사용하지 않는다. 변경 전후 비교는 위의 동일 부하 CPU 미세 측정을 사용한다.
